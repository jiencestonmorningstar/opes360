# Domain Event Bus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the missing *trigger* half of trigger → condition → action. Modules
announce what happened; automation rules and notifications listen. Nothing
polls, and no module imports another to find out something occurred.

**Architecture:** One `DomainEvent` value object carrying a name, a company, a
subject and a payload, dispatched through Laravel's existing event dispatcher.
`AutomationRule` rows match an event name plus the **same condition matcher the
workflow engine already uses**, and fire actions. Delivery to the outside world
reuses the existing webhook dispatcher — there is no second delivery path.

**What this is not.** Not a queue, not a message broker, not a second
notification system. It is a naming convention plus a rules table.

**Tech Stack:** Laravel 12, Pest/PHPUnit. No new Composer packages.

**Roadmap item:** 1.3. **Spec:** §54 and §59 of the master spec; ERP #20's
automation half.

---

## Decisions taken

| # | Decision | Why |
|---|---|---|
| 1 | Reuse `WorkflowConditions` for rule matching | The matcher already exists, is tested, and fails closed. A second condition language would be the exact duplication the brief forbids |
| 2 | Reuse `WebhookDispatcher` for outbound delivery | §33 and §59: existing notification and delivery infrastructure, never a second one |
| 3 | Events carry a **subject reference**, not a serialised subject | A payload that embeds a copy of an invoice is a copy of an invoice, which is what the brief spends §56 forbidding |
| 4 | Rules are rows, matched at dispatch; actions are a small closed set | An action typed into an admin form must never be executable code — the same reasoning as workflow conditions |
| 5 | A failing rule never breaks the thing that emitted the event | An automation that stops an invoice being issued is worse than an automation that does not run |

---

## The action set

Deliberately small and closed. Each is a verb the product already performs:

| Action | Effect |
|---|---|
| `start_workflow` | Start a named workflow against the event's subject |
| `notify_user` / `notify_role` | Send through the existing notification layer |
| `send_webhook` | Hand to the existing `WebhookDispatcher` |
| `set_field` | Set one allow-listed field on the subject |

Anything outside this set is refused at validation time, not at dispatch time.

- [ ] **Step 3: `app/Events/DomainEvent.php`**

```php
<?php

namespace App\Events;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Foundation\Events\Dispatchable;

/**
 * Something happened, said once, in a form anything can listen to.
 *
 * One class rather than one per event: the name is data. Sixty event classes
 * would mean sixty files that differ only in a string, and an automation rule
 * that wanted to match on a name would have to map class names back to it
 * anyway.
 */
class DomainEvent
{
    use Dispatchable;

    public function __construct(
        public readonly string $name,
        public readonly string $companyId,
        public readonly Model $subject,
        public readonly array $context = [],
        public readonly ?int $actorId = null,
    ) {}

    /**
     * A reference, never a copy.
     *
     * Whoever handles this can load the record — and will get the current one,
     * with the current permissions applied, rather than a snapshot that has
     * silently drifted.
     */
    public function payload(): array
    {
        return [
            'event' => $this->name,
            'company_id' => $this->companyId,
            'subject_type' => $this->subject->getMorphClass(),
            'subject_id' => $this->subject->getKey(),
            'actor_id' => $this->actorId,
            'context' => $this->context,
        ];
    }
}
```

- [ ] **Step 4: `app/Support/DomainEvents.php`** — a flat catalogue constant of

- [ ] **Step 5: The trait**

```php
<?php

namespace App\Models\Concerns;

use App\Events\DomainEvent;
use App\Support\CurrentCompany;

trait EmitsDomainEvents
{
    public function emitDomainEvent(string $name, array $context = []): void
    {
        $companyId = $this->getAttribute('company_id') ?? app(CurrentCompany::class)->id();

        if ($companyId === null) {
            return;
        }

        DomainEvent::dispatch($name, $companyId, $this, $context, auth()->id());
    }
}
```

### Task 2: Automation rules

**Files:** the migration, `app/Models/AutomationRule.php`,
`tests/Feature/Automation/AutomationRuleTest.php`

Columns: `id`, `company_id`, `name`, `event` (the trigger name), `conditions`
(json — **the same shape `WorkflowStep.conditions` uses**), `action`,
`action_config` (json), `is_active`, `last_fired_at`, `created_by`, timestamps,
soft deletes. Index `['company_id', 'event', 'is_active']`.

Tests: a rule matches its event and ignores others; conditions are evaluated
with `WorkflowConditions` against the subject; an inactive rule never fires; a
rule belonging to another company never fires; an unknown action is refused at
validation.

        foreach ($rules as $rule) {
            try {
                $this->runner->run($rule, $event);
            } catch (Throwable $e) {
                // An automation that stops an invoice being issued is worse
                // than an automation that does not run. Log it and carry on;
                // the emitting code must never learn that a listener failed.

does not break the emitter**; two rules on one event both fire; `last_fired_at`
is stamped; `start_workflow` actually starts one; `set_field` refuses a field
outside the allow-list.

## Testing plan

| Risk | Test |
|---|---|
| An automation breaks the business action that emitted it | `test_a_throwing_rule_does_not_break_the_emitter` |
| A payload becomes a second copy of an ERP record | `test_the_payload_references_the_subject_rather_than_copying_it` |
| An admin-typed action executes as code | `test_an_unknown_action_is_refused` |
| A rule fires across tenants | `test_a_rule_belonging_to_another_company_never_fires` |
| A second condition language appears | The rule model imports `WorkflowConditions`; there is no other matcher |
