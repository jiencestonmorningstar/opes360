# 2.17 — Watermarks & print control

## What was built

One watermark layer over the existing print pipeline — CSS only (fixed,
rotated overlay + fixed footer line, print-color-adjust for the dialog), no
PDF library, works on shared hosting.

### Pieces

- `app/Support/Watermarks.php` — the one place that decides what a printed
  page says about itself:
  - `statusMark($paper, $isCopy)` → `DRAFT` / `VOID` / `COPY` / null. An
    issued paper viewed through a share link is `COPY`; a draft or void stays
    `DRAFT`/`VOID` even on a share, because `COPY` would upgrade its apparent
    validity.
  - `confidentialFooter($paper, $company, $viewer)` → `CONFIDENTIEL —
    {company} · {viewer} · {timestamp}` for confidential-and-above, honouring
    the per-company toggle; null otherwise.
  - `shareIdentity($share)` → `Lien {first 8 of token}` — traceable via the
    share access log without printing a reusable token.
- `resources/views/print/partials/watermark.blade.php` — the overlay itself.
  `position: fixed`, so the diagonal mark repeats on every printed page.
- `resources/views/print/paper.blade.php` — includes the partial.
- `resources/views/shares/show.blade.php` — includes it on the `found`
  branch; viewer identity is the share link, never a user's name, and the
  company is the share's own tenant (resolved inside `CurrentCompany::as`),
  so a token page cannot leak another tenant's name.
- `app/Http/Controllers/PrintController::paper()` — additive: passes the two
  watermark strings, and records an `exported` audit row (subject-bearing
  `Audit::record`, same tier as `Audit::exported` — never windowed, two
  prints = two rows) when the paper is confidential or restricted.
- Migration `2026_09_14_000101_add_confidential_print_footer_to_companies.php`
  — `companies.prints_confidential_footer` boolean, DB default `true` (no
  `create()` backfill), cast added on `Company`.

## Decisions worth knowing

- **Status marks are not configurable and never will be.** The toggle governs
  only the confidential footer (provenance). DRAFT/VOID speak to validity — a
  draft that prints clean is indistinguishable from an issued document. The
  test `the_company_toggle_removes_the_footer_but_never_the_status_mark`
  pins this.
- The audit row fires for confidential *and* restricted (`isConfidential()`
  is "confidential and above"), on opening the print view — the next click
  is the print dialog.
- Share-path prints write no `exported` row: there is no authenticated actor,
  and every share view is already logged in `business_document_share_accesses`.
