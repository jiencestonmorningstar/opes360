## Things you need to add (I could not)

1. **Routes** — no API or web routes exist for any of the three. Suggested REST
   shape: `positions`, `employees/{employee}/attendance`,
   `employees/{employee}/reviews`.
2. **Permissions** — no abilities were registered. Suggested:
   `positions.view/manage`, `attendance.view/record`, `reviews.view/manage`,
   plus a rule that an employee may read and acknowledge only *their own*
   review. Until abilities exist, nothing gates these models but tenancy.
3. **Role seeding** — grant the above in `RolePermissionSeeder`.
4. **Module config** — attendance and performance reviews are plausible members
   of the HR module in `config/modules.php`. Positions should **not** be, for
   the same reason departments are not: an employee's job title outlives a
   business switching payroll off.
5. **API resources / docs** — `EmployeeResource` still exposes only the
   free-text `job_title`. If you add `position`, add it *alongside* the string,
   never in place of it.
6. **Team screens** — `app/Livewire/Team/*` still writes `job_title` as free
   text. Moving them to a picker is the step that eventually lets the string
   column go.

## The `job_title` shadowing trap

`employees.job_title` was **kept and backfilled**, not dropped — the same call
made for `department`, and for the same reasons (the API exposes it, payroll
snapshots it onto payslips, and a backfill that merged two spellings must be
visible and fixable).

The relation is therefore `Employee::positionRecord()`, not `jobTitle()`.
Eloquent resolves an attribute before it looks for a relation, so a relation
named `jobTitle` would return the typed string forever with nothing erroring —
exactly the bug `departmentRecord()` was named around. `position` happens to be
free of the collision today, but naming the two links inconsistently invites
somebody to "tidy" the older one back into the trap. A test pins the reasoning:
`PositionTest::test_the_free_text_job_title_and_the_relation_are_different_things`.

## Attendance is deliberately NOT wired to payroll

Payroll reads the employment contract in force on the payslip's own date so a
June payslip reproduces June forever. Attendance is corrected long after the
fact. If a calculation reached into `attendance_records`, fixing last month's
timesheet would silently rewrite a payslip already paid and declared to the
CNPS. Any absence deduction must be an explicit salary component entered onto
the run, where a human can see it.
`AttendanceTest::test_attendance_does_not_reach_payroll` asserts
`PayrollRunner` never mentions the table. Do not "improve" this without a
design for immutably snapshotting attendance onto the run first.

## Recruitment is excluded

The gap analysis lists recruitment under the same checklist item. It is a
genuinely separate module — candidates, applications, stages, interviews,
scorecards, offer letters, and a public-facing application form with file
uploads — with almost no schema overlap with what is here beyond eventually
creating an `Employee`. Bundling it would have roughly doubled this change and
made it unreviewable. It should be its own phase, and `positions` is the right
thing for a future job requisition to point at.

## Smaller decisions worth knowing

- One attendance row per employee per day, enforced by a unique key
  (`attendance_company_employee_day_unique`), not by the writing code. A
  re-import must overwrite, not append — a duplicate day doubles every total
  built on the table with no way for a reader to tell which row is real.
- `minutes_worked` is derived from the two clock times only when it was not
  supplied; device imports carry a duration and no times, and recomputing would
  overwrite the authoritative figure.
- `AttendanceRecord::forPeriod()` bounds on whole days. The `date` cast stores
  midnight timestamps, so a naive `whereBetween` against the string dropped the
  last day of the range — caught by a test during this work.
- Acknowledging a performance review freezes the verdict (rating, summary,
  strengths, improvements, goals, period, cycle, reviewer, position). The
  employee's own comment stays editable. An acknowledgement of a document that
  can still be edited is worth nothing in the dispute it is kept for.
- Table is `performance_reviews`, not `employee_performance_reviews`: the
  longer name pushes generated index and FK identifiers past MySQL's
  64-character limit, which SQLite would have accepted silently. Long indexes
  on both new tables are named explicitly.
- `recorded_by`, `reviewer_id`, `created_by` are `foreignId` (users.id is a
  BIGINT); `employee_id` and `position_id` are `foreignUlid`.
- Deleting a position or a department nulls the link and never deletes people
  or reviews. Attendance does cascade with a force-deleted employee — it is
  about that one person and nobody else.

## Screens (added later, over the same backend)

Three Livewire components and their views. Nothing outside these files, plus
`tests/Feature/Hr/HrScreensTest.php`, was touched.

- `App\Livewire\Business\Positions` + `livewire.business.positions` — the list
  of posts, deliberately the Departments screen with different nouns.
- `App\Livewire\Hr\Attendance` + `livewire.hr.attendance` — a period of days,
  totals per person, and the entry form.
- `App\Livewire\Hr\Reviews` + `livewire.hr.reviews` — two tabs: everybody's
  (needs `reviews.view`) and mine (needs nothing but being the subject).

### Route lines still needed

```php
use App\Livewire\Business\Positions as BusinessPositions;
use App\Livewire\Hr\Attendance as HrAttendance;
use App\Livewire\Hr\Reviews as HrReviews;

Route::get('/business/positions', BusinessPositions::class)
    ->middleware('can:positions.view')->name('positions');

Route::get('/hr/attendance', HrAttendance::class)
    ->middleware('can:attendance.view')->name('attendance');

// No `can:` middleware, on purpose. An employee with no HR permission at all
// still has to reach their own review to acknowledge it — being its subject is
// the permission. The component shows the "everybody's" tab only to holders of
// `reviews.view` and refuses (403) any acknowledgement of somebody else's.
Route::get('/hr/reviews', HrReviews::class)->name('reviews');
```

`/hr/…` rather than `/team/…`: `/team/{employee}` is declared in the same group
and would swallow `/team/attendance` as an employee ULID.

### Nav entries still needed

`resources/views/partials/business-tabs.blade.php`, after Departments — the two
screens are the same kind of list and users will look for them together:

```php
['label' => 'Positions', 'route' => 'positions', 'icon' => 'briefcase'],
```

The two HR screens want links from the Team area (sidebar or a link beside the
Team heading), both under the existing `team` nav highlight — the components
already pass `'active' => 'team'`. Reviews should be linked for everybody, not
only for holders of `reviews.view`, or an employee cannot find the review they
are being asked to sign.

### Decisions inside the screens

- `attendance.record` is gated separately from `attendance.view` in every write
  method, and the entry form and the row buttons are wrapped in
  `@can('attendance.record')`. A supervisor with `view` gets a table and no way
  to type into it.
- A day that already exists is **updated**, never appended. The lookup uses
  `whereDate`, because the `date` cast writes a midnight timestamp and matching
  on the bare date string finds nothing on SQLite — the correction would then
  land as a second row and hit the unique key in the user's face.
- `minutes_worked` is blanked when the user did not type it, so the model
  re-derives it from the corrected times rather than keeping the figure the
  correction was fixing.
- The attendance screen states in plain words that these hours are not a pay
  calculation. Nothing on it is labelled as a deduction or an amount.
- Acknowledgement is warned about before the button, not after: the employee is
  told which fields freeze and that their own comment does not.
- The free-text `job_title` is untouched — no picker was added to the Team
  screens, so payroll's snapshot behaviour is exactly as it was.
