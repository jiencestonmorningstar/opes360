## 1. Register the listener (required)

`app/Providers/AppServiceProvider.php`, next to the existing
`TranslateDocumentWorkflowEvents` line:

```php
use App\Listeners\PostApprovedExpenseClaims;

Event::listen(DomainEvent::class, PostApprovedExpenseClaims::class);
```

Without it a claim still approves correctly — the engine is the authority —
but the charge and the staff debt are not written to the books until
`reimburse()` runs, which calls `postApproval()` itself as a backstop. The
listener is what makes an approved-but-unpaid claim show as a liability.

## 2. Permissions

Please add to `app/Support/Permissions.php` and `RolePermissionSeeder`, in the
**Expenses** group alongside the existing `expenses.*` abilities:

| Ability | Who should hold it |
|---|---|
| `expense_claims.view` | Owner, Administrator, Manager, Accountant, Staff (own claims) |
| `expense_claims.create` | Owner, Administrator, Manager, Accountant, Staff |
| `expense_claims.reimburse` | Owner, Administrator, Accountant |

Deliberately **no** `expense_claims.approve`. Approving is the workflow
engine's business and `docs/workflows.md` is explicit that being asked *is*
the permission; a separate ability would let an approver the engine had just
assigned be refused.

## 3. Routes

None are needed for the service to work — there is no UI or API controller in
this phase. If you want them wired now:

- `GET /expense-claims` → list (gate `expense_claims.view`)
- `GET /expense-claims/{claim}` → show
- `POST /api/expense-claims` → `create` + optional `submit`
- `POST /api/expense-claims/{claim}/reimburse` → `reimburse`

## 4. Workflow definition

`ExpenseClaim::class` needs to be an allowed `subject_type` wherever the
workflow-definition screen lists approvable models (there is a hard-coded list
in the workflow admin Livewire component). Label it "Expense claim".

`submit()` falls back to `Workflow::defaultFor(ExpenseClaim::class)` when no
workflow is passed and throws a clear `RuntimeException` if none is defined.

## Calls made, worth knowing about

- **Account 422 (`staff_payable`)**, not 401, holds what is owed to the
  employee between approval and payment. Putting staff in payables would make
  the supplier ageing report start chasing the person who paid for the taxi.
  422 is shared with payroll's "rémunérations dues" — if you want them
  separated, 4211 is the natural split and is a one-line change in
  `ExpenseClaimService`.
- **Cost centre allocation lives on the claim line, not on the journal line.**
  `journal_lines` has a `cost_centre_id` column (added in the fiscal-periods
  migration) but `Ledger::post()` accepts no per-line cost centre, and
  `app/Services/Accounting/*` was off-limits. Budget reporting therefore joins
  through `expense_claim_lines`. If you want it on the ledger, adding a
  `cost_centre` key to `Ledger::post()`'s line array is the whole change and
  this service can pass it in one line.
- **`status` on the claim is a cache, not an authority.** `isApproved()` reads
  the engine. The column exists for listing and filtering.
- Claim `number` is nullable and unpopulated — no sequence was invented, since
  `DocumentNumbers` is document-specific and inventing a second numbering
  scheme seemed worse than leaving it for the screen that needs it.
