# §2.15 Alerts & §2.20 Documents-panel coverage — handoff

## §2.15 — `opes:remind-actions`

`app/Console/Commands/RemindOutstandingActions.php`. A daily sweep that raises
domain events — it never mails anyone itself. The events flow through
`RunNotificationRules` → `NotificationDispatcher`, so rules, recipients,
mutes, quiet hours, digests and dedupe all apply exactly as for any other
notification.

Events raised (added to `App\Support\DomainEvents`):

| Event | When |
|---|---|
| `workflow.assignment.overdue` | A pending `WorkflowAssignment` whose `due_on` is strictly before today (dates compared as dates — an item due *today* is not overdue). |
| `document.expiring` | A non-void `BusinessDocument` inside the expiry window (`DocumentAnalytics::EXPIRY_HORIZON_DAYS` = 30 — the same horizon as the workspace counter). |
| `document.signature.overdue` | A document with pending signature requests older than `--signature-days` (default 3), grouped one event per document. |

`WorkflowAssignment` now uses `EmitsDomainEvents` so the assignment itself is
the event subject (per-assignment dedupe fingerprint at the dispatcher).

**Once per subject per day**, whatever a rule's `dedupe_minutes` says: before
raising an event the command checks `notification_deliveries` for the same
event + subject since the start of today — the dispatcher's own log is the
fingerprint, so a re-run raises nothing. A day with nothing due is a no-op.

No rules ship by default: a business opts in by creating a notification rule
listening for these events (Settings → Notification rules).

### Schedule line

`routes/console.php` was deliberately not edited by this task. Add:

```php
/*
 * The daily nudge for everything still waiting on somebody: overdue
 * approvals, expiring documents, unanswered signature requests. The command
 * is a no-op when nothing is due, and fingerprints against the delivery log
 * so a double run cannot double-remind.
 */
Schedule::command('opes:remind-actions')
    ->dailyAt('07:30')
    ->withoutOverlapping();
```

### Tests

`tests/Feature/Documents/RemindersTest.php` — 6 tests, proving deliveries via
real `NotificationDelivery` rows (never `Event::fake()`): exactly one delivery
per overdue assignment; a second same-day run adds none; due-today is not
overdue; nothing due sends nothing; expiry window respected; answered
signatures silent.

## §2.20 — documents (Library) panel inventory

`<x-documents.library-panel :record="…" />` embeds anywhere; it asks
`DocumentLinker` for the record's papers.

| Record screen | Status |
|---|---|
| Contract — `livewire/contracts/show.blade.php` | Already had it |
| Contact/Customer — `livewire/customers/show.blade.php` | Already had it |
| Employee — `livewire/team/show.blade.php` | **Added** (Profile tab) |
| Service ticket — `livewire/service/show.blade.php` | **Added** (below the timeline) |
| Project | No record show screen exists (`livewire/projects/index.blade.php` only) — nothing to embed on |
| Deal | No show screen (`deals/index` + slide-over form) — nothing to embed on |
| Fixed asset | No show screen (`assets/index` + movements) — nothing to embed on |
| Expense | No show screen (`expenses/index` only) — nothing to embed on |

When Project/Deal/FixedAsset/Expense grow show screens, the one-liner is
`<x-documents.library-panel :record="$model" />`.
