# 2.16 — Bulk operations (papers workspace)

## What shipped

- **`app/Services/Documents/BulkActions.php`** — move, tag, untag, classify,
  archive, zip. Each action is the existing single-document path run N times:
  one `DB::transaction` per item, `Gate::forUser($actor)` asked per item
  (`file` for filing actions, `void` for archive, `view` for download). No
  mass UPDATE anywhere, so the policy, the `AuditObserver` (one `updated`
  audit row per item), the issued-document guard in
  `BusinessDocument::booted()`, and the versioner all fire exactly as they do
  for one document.
- **Domain events** — filing actions emit `document.updated`
  (with a `change` context: moved/tagged/untagged/classified); archive emits
  `document.archived`. These were catalogue-only before; nothing else emitted
  them.
- **`app/Livewire/Papers/Index.php` + `resources/views/livewire/papers/index.blade.php`**
  — checkbox per row, Select page / Clear, and a bulk bar (visible only with
  a selection): Move-to-folder, Add/Remove tag, Classify, Archive
  (wire:confirm), Download ZIP. The outcome sentence renders in a status
  banner (`$bulkSummary`, a component property, not a session flash).
- **`app/Services/Documents/DocumentBundles.php`** — refactored: new public
  `zipDocuments(iterable)` extracted from `zipPackage()`, which now delegates.
  Bulk download reuses the same packager (duplicate-name suffixing, README
  fallback for the ZipArchive-writes-nothing-when-empty case).
- **`tests/Feature/Documents/BulkActionsTest.php`** — 12 tests, 38 assertions.
  Full `--filter="Bulk|Papers|Document"` run: 478 passed.

## Refusal semantics

A refused item is skipped **and named**; the rest of the batch completes.
The summary is one sentence: `3 moved, 1 refused: Contract X — it is under
legal hold.`

- **Archive = void**, matching the workspace's existing "Archived" counter
  (`status = 'void'`). Runs through `DocumentComposer::void()`, so the
  verification token is revoked per item.
- **Legal hold**: an archive of a held document is refused by name
  ("it is under legal hold") and the document is not touched.
- **Drafts**: archive refuses them with the composer's own message ("Only an
  issued document can be voided.").
- **Restricted papers**: a user without `papers.manage` has them dropped at
  two layers — the Livewire component refetches the selection through
  `readableBy()` (a smuggled id for an unreadable document never reaches the
  loop, so the report cannot leak its title), and the per-item `file`/`void`
  policy check refuses any that survive.
- **Issued documents**: filing (move/tag/classify) is allowed — filing is not
  content, same as singles. Content stays frozen by the model guard.
- **Download**: silently filters to `view`-authorized documents; composed
  (fileless) documents are skipped by the packager as in package downloads.
- Untagging a document that never had the tag is success, not a refusal.

## Wiring you may want

- `document.updated` / `document.archived` are now emitted from BulkActions
  only. If singles (LibraryController::update, Composer void outside bulk)
  should emit them too, that is a separate small change.
- Bulk share / export / assign / workflow-submission (§64–68 also lists them)
  are not built; `BulkActions::each()` is the ready-made loop for them.
- Selection is per-screen state; it does not persist across filters
  deliberately (changing a filter keeps checked ids — they are refetched
  through the readable scope at action time, so this is safe).
