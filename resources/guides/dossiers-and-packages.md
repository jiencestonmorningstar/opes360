# Dossiers, packages and checklists

Three ways of seeing documents together that are not folders.

## A customer's dossier

Every customer, supplier, employee or project already shows the documents
filed against it, grouped by kind — contracts together, letters together,
certificates together.

This is a **view of the documents themselves**, not a separate record. There
is no dossier to create, maintain, or keep in step: link a document to a
customer and it appears; unlink it and it does not. Nothing can drift out of
date, because there is nothing stored to drift.

## Packages

A package is a named group — "Annual Audit Package 2026" — pulling together
documents that belong to one piece of work but live in different folders and
belong to different customers.

A package holds **references**, not copies. Removing a document from a
package leaves the document exactly where it was; deleting a package deletes
none of what it grouped. A package can be **closed** once assembled, which
stops anything further being added until it is reopened.

A whole package can be downloaded as a single ZIP file. Documents in it that
were written from a template — rather than uploaded as files — are simply not
in the archive, since there is no file to include; the rest still download.

## Checklists

A checklist says what a record needs before it is complete — a supplier needs
a registration document, a tax certificate, and a signed agreement.

It is answered by looking at what is actually linked to the record right now,
never by a tick somebody has to remember to set. Attach the missing
certificate and the checklist updates itself; unlink it again and the
checklist says it is missing once more. A "complete" mark that could disagree
with the documents underneath it would be worse than no checklist at all.

## Things that surprise people

**A document can be in any number of packages at once** and still sit in
exactly one folder. Folders are where a document lives; packages are what it
is being used for.

**Downloading a package as a combined PDF is not available yet.** ZIP is.
Producing one merged PDF needs a server-side PDF engine OPES360 does not have
— printing is handled by your browser today — and that is a deliberate open
decision rather than something missing by oversight.
